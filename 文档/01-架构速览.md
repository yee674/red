# 红脉智谱 RedTrace AI —— 架构速览（答辩可直接照着讲）

> 主标题：**红脉智谱（RedTrace AI）**　副标题：**一师红色文化知识图谱与智能研学平台**　
> 功能标签：**关系挖掘 · 人物追踪 · AI 定制路线**

## 一句话

> 用 C 语言写图（邻接表 + BFS），用 Python 封装成 Web 服务，把 33 个一师红色文化实体连成知识图谱，再在上面做「问答 + 可视化 + 研学」三层应用。

### 三个功能标签对应的技术点

| 标签 | 技术支撑 | 代码位置 |
| --- | --- | --- |
| 关系挖掘 | 47 条关系 + C 邻接表一跳查询 + BFS 最短路径（两点怎么连） | `graph.c: query_neighbors / find_path`、`app.py: render_entity_card / render_path_card` |
| 人物追踪 | 9 位人物的师友关系链，卡片里关联实体可点、图谱里点节点高亮邻居 | `kg.json: edges`、`app.py: render_relation_chips`、`ui_graph.py` |
| AI 定制路线 | 实体类型匹配 + C-BFS 跳数就近排序 + 贪婪最近邻排线，自动生成地图/讲解/任务卡 | `custom_route.py`、`app.py: _render_custom_route` |

## 1. 数据流

```
你的 Word 资料（含来源）
        │  人工整理 + 程序解析
        ▼
   kg.json（实体 / 关系 / 别名 / 来源链接）
        │
        ├──────────────► materials/<id>.md     ← 每实体一页资料（中英）
        │                assets/<id>.jpg        ← 配图（Commons / 网络检索 / 示意图）
        │
        ▼  c_core.build_and_load()
   nodes.txt / edges.txt（C 认识的纯文本）
        │
        ▼  load_graph()
   graph.dll（C 内核）
   ├─ 有向邻接表 firstEdge  → query_neighbors()  一跳查询
   └─ 无向邻接表 firstU     → find_path()        BFS 最短路径
        │
        ▼  ctypes
   Python（GraphLib）→ Streamlit 三个页面
        │
        ├─ 问答页：实体卡片 / 两点关系 / 未命中建议
        ├─ 图谱页：力导向图 + 时间轴
        └─ 研学页：地图路线 / 点位讲解 / 任务卡 / 测评 / 导出 docx
```

**热加载**：每次数据变动会按 `nodes.txt + edges.txt` 算签名，把 `graph.dll` 复制成
`_runtime/graph_<签名>.dll` 再加载 —— 文件名不同，Windows 就当新模块，全局变量从零开始，
于是改完 JSON 不用重启、不用重新编译；同一签名只 `load_graph()` 一次，避免节点重复。

## 2. C 内核接口（`graph.c`，Python 用 ctypes 调）

| 函数 | 签名 | 作用 | 返回 |
| --- | --- | --- | --- |
| `graph_api_version` | `int(void)` | 内核版本（当前 2） | 2 |
| `load_graph` | `void(void)` | 读 `nodes.txt` / `edges.txt`，建有向 + 无向两张表 | — |
| `query_neighbors` | `int(const char* id, char* buf, int n)` | 一跳邻居（有向） | 条数，-1 表示没找到 |
| `find_path` | `int(const char* a, const char* b, char* buf, int n)` | BFS 最短路径 | 跳数；0 同一节点，-1 不连通 |
| `get_node_count` / `get_edge_count` | `int(void)` | 规模统计 | 数量 |

**输出格式**

- `query_neighbors`：`目标名|关系;目标名|关系;`
- `find_path`：`id0|rel|id1|~rel|id2`，`~` 表示这条边在原始数据里方向相反

**算法细节（可以写成板书那种）**

1. BFS 用静态数组当队列（`bfsQueue`），`bfsPrev` 记父节点、`bfsPrevRel` 记走哪条边、`bfsPrevRev` 记方向；
2. **先只走正向边**跑一次 BFS —— 这样输出是「毛泽东 —同学→ 蔡和森」的自然方向；
3. 找不到再允许走反向边，反向边在输出里加 `~`，前端画成 `← 老师 —`；
4. 所有 `snprintf` 都带长度检查，缓冲区不够就停，不会越界（C 里最容易出事的地方）。

**上限**：200 节点 / 600 边（`MAX_NODES` / `MAX_EDGES`），超了 `c_core` 会给出中文报错而不是让 C 越界。

## 3. 三个页面

| 页面 | 关键代码 | 数据来源 |
| --- | --- | --- |
| 💬 问答 | `app.py: render_chat_page()` / `render_entity_card()` / `render_path_card()` | `kg.json` + `materials/` + `graph.dll` |
| 🕸️ 知识图谱 | `app.py: render_graph_page()` + `ui_graph.py` | `kg.json` + `content/timeline.json` |
| 🎒 研学 | `app.py: render_study_page()` / `_render_custom_route()` + `custom_route.py` + `ui_map.py` + `report.py` | `content/routes.json` + `content/quiz.json` + `kg.json` |

**交互闭环**：图谱里选中实体 → 跳问答页看卡片；研学地图点地标 → 弹出地址/照片/简介 → 「查看实体卡片」跳问答页；测评错题解析里写清考点，对应实体在卡片里可继续追问。

### AI 定制路线的三步

```
选 兴趣主题(kind) + 时长(hours) + 起点(start)
        │
        ├─ 1. 主题匹配：poi.entity.type == kind  → 加分
        ├─ 2. 距离：lib.find_path(start, poi.entity) 的跳数（C BFS）
        ├─ 3. 排序：从 start 出发做贪心最近邻（每次挑跳数最小的下一个点）
        ▼
   路线点位序列 → 地图打点 + 讲解卡片 + 3 条自动任务 + 可导出 docx
```

数量规则：2 小时→3 个点位、3 小时→4 个、4 小时→6 个；起点必选。
整个过程只用图谱数据与 C 的 BFS，不调用大模型，所以结果可复现、可解释。

## 4. 双语怎么做的

- 界面文案：`app.py` 的 `TEXT = {"zh": {...}, "en": {...}}`；
- 实体名：`kg.json` 的 `name` / `name_en`，取用走 `display_name(node, lang)`；
- 资料正文：`materials/<id>.md`（中）与 `<id>.en.md`（英），按当前语言挑；
- 关系标签：`REL_LABELS` 一行两列（`"TEACHER_OF": ("老师", "Teacher of")`）；
- 图片署名：`image_credit` / `image_credit_en`；
- 研学内容：`routes.json` / `quiz.json` / `timeline.json` 里带 `*_en` 字段，按语言回退。

## 5. 技术亮点（按说服力排序）

1. **真在 C 里算**：不是「Python 查字典假装调 C」——一跳与 BFS 都在 `graph.dll` 内完成，页面还提供「查看 C 层原始返回」和每次查询的 µs 耗时。
2. **热加载设计**：解决「C 静态数组 + DLL 只加载一次」的经典坑，改数据零重启。
3. **离线可用**：力导向图自写 canvas；地图内联 Leaflet（瓦片联网时才需要）。
4. **可核验的准确性**：每条事实挂来源链接，资料与图谱同源，避免模型幻觉（本项目未引入大模型生成）。
5. **工程完整度**：双语、自动刷新、研学闭环、docx 导出、错误可读（上限/字段/旧内核都有中文提示）。

## 6. 已知限制（主动说比被问出来好）

- 33 实体规模偏小，关系类型只有 19 种，缺少时间/坐标等属性字段；
- 点位坐标是近似值，仅用于导览示意；
- 尚未接入大模型：不会做「自然语言理解 + 生成式讲解」，问答是图谱检索式回答；
- 图片中 13 张来自网络检索（非 PD/CC），作业提交需按学校要求注明出处。
